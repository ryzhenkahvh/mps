# Сервер сообщества

Раздел «Сообщество» работает на бесплатном проекте [Supabase](https://supabase.com): аккаунты, база данных
и хранилище файлов. Своего сервера нет — приложение обращается к Supabase напрямую, а что кому разрешено,
решают правила в базе (`schema.sql`), поэтому публичный ключ можно спокойно хранить в репозитории.

## Настройка (один раз)

1. Создайте проект на supabase.com (регион — ближайший к вашим слушателям, например Frankfurt).
2. **SQL Editor** → вставьте весь файл [`schema.sql`](schema.sql) → **Run**. Скрипт можно запускать повторно:
   опубликованное он не трогает.
3. **Authentication → Sign In / Providers → Email**: выключите **Confirm email** и сохраните.
   Встроенная почта Supabase шлёт письма только участникам вашей команды в Supabase (и не больше двух в час),
   поэтому с включённым подтверждением никто, кроме вас, зарегистрироваться не сможет. Если подтверждение
   нужно, подключите свою почтовую службу (Authentication → Emails → SMTP Settings).
4. **Project Settings → API Keys**: скопируйте публичный ключ (`publishable`, он же `anon`) и адрес проекта
   в файл [`cloud.properties`](../cloud.properties) в корне репозитория:
   ```
   url=https://ваш-проект.supabase.co
   key=sb_publishable_...
   ```
   Секретный ключ (`secret` / `service_role`) в приложение класть нельзя.
5. Соберите приложение. Пока `key` пуст, раздел «Сообщество» показывает, что он не подключён.
6. Чтобы стать модератором: **Table Editor → mps_profiles**, в своей строке поставьте `is_admin = true`.

## Вход через Google (по желанию)

Вход идёт через браузер, поэтому отпечатки ключей подписи приложения не нужны.

1. [Google Cloud Console](https://console.cloud.google.com) → APIs & Services → Credentials →
   **Create credentials → OAuth client ID → Web application**.
   В **Authorized redirect URIs** добавьте `https://ваш-проект.supabase.co/auth/v1/callback`.
2. Supabase → **Authentication → Sign In / Providers → Google**: включите и вставьте Client ID и Client Secret.
3. Supabase → **Authentication → URL Configuration → Redirect URLs**: добавьте `jxpix.proger.mps://auth`.

Кнопка «Войти через Google» появится в приложении сама: оно спрашивает у сервера, включён ли этот способ.
Имя человеку в этом случае подбирается автоматически, поменять его можно в профиле.

## Что есть на сервере

| Таблица | Что в ней |
|---|---|
| `mps_profiles` | имя, пара слов о себе, цвет аватара; создаётся сама при регистрации |
| `mps_items` | всё опубликованное: звуки, пресеты, проекты, треки |
| `mps_ratings` | оценки от 1 до 5, по одной от человека; свою работу оценить нельзя |
| `mps_downloads` | кто что скачал — чтобы считать скачивание один раз |
| `mps_reports` | жалобы |
| `mps_config` | лимиты (одна строка, можно менять в Table Editor) |

Всё, что создаёт скрипт, начинается с `mps_`: таблицы, функции и файлы, которые уже есть в проекте
(например, своя таблица `profiles`), он не трогает.

Файлы лежат в хранилище `mps-files`, у каждого автора своя папка. Пресеты файлов не имеют: это только
положения ручек, они хранятся прямо в таблице, а послушать пресет приложение даёт на собственном инструменте.

## Лимиты бесплатного тарифа

На бесплатном тарифе 1 ГБ файлов, 5 ГБ скачиваний в месяц, файл до 50 МБ. Чтобы один человек не занял всё место:

- автору — 50 МБ (`user_quota_bytes`), всему хранилищу — 900 МБ (`total_quota_bytes`);
- один файл — до 10 МБ; приложение отправляет звук до 5 МБ, проект до 8 МБ, трек в MP3 до 10 МБ
  (длинный трек сжимается сильнее);
- не больше 40 публикаций в день от одного автора (`daily_items`).

Счётчик скачиваний считает и тех, кто не вошёл (по случайному номеру установки приложения), поэтому его
можно накрутить. На оценки это не влияет: оценивать могут только вошедшие, по одной оценке на публикацию.

Бесплатный проект «засыпает», если к нему неделю никто не обращался. Данные при этом не пропадают:
проект включается кнопкой в консоли Supabase.

## Модерация

Под каждой публикацией есть «Пожаловаться». После трёх жалоб от разных людей (`hide_after_reports`)
публикация скрывается: её видят только автор и модераторы. Модератор (`mps_profiles.is_admin`) видит в приложении
фильтр «Скрытые» и может вернуть публикацию или удалить её. Удалить можно и в консоли: Table Editor → `mps_items`
(файл при этом удалите в Storage → `mps-files`).

Удалённый файл перестаёт отдаваться по прямой ссылке не сразу: сеть доставки забывает его в течение минуты.

## Что покажет Security Advisor

В консоли Supabase (Advisors → Security) останется несколько предупреждений. Они ожидаемы:

- «Function … can be executed … as SECURITY DEFINER» — про функции, которые делают то, что самому человеку
  запрещено: считают скачивания (`mps_add_download`), удаляют его собственный аккаунт (`mps_delete_account`),
  скрывают публикации, проверив, что вызвавший — модератор (`mps_moderate`), считают занятое место
  (`mps_storage_used`, `mps_storage_total`). Каждая из них сама проверяет, кто её вызвал.
- «RLS enabled, no policy» у `mps_downloads` — к этой таблице доступа нет ни у кого, с ней работает только
  функция подсчёта.
- Предупреждение про `rls_auto_enable` относится к функции самого Supabase (опция «включать RLS автоматически»).

## Если `supabase.co` не открывается

У части мобильных операторов адреса `*.supabase.co` недоступны. Приложение умеет ходить через запасной адрес:
если основной не отвечает, оно пробует `fallbackUrl` из `cloud.properties`. Запасной адрес — это любой
пересыльщик на другом домене, который передаёт запросы в проект как есть. Например, Cloudflare Worker:

```js
export default {
  async fetch(request) {
    const url = new URL(request.url);
    // только то, чем пользуется приложение
    if (!/^\/(auth|rest|storage)\/v1\//.test(url.pathname)) return new Response("Not found", { status: 404 });
    return fetch(new Request("https://ваш-проект.supabase.co" + url.pathname + url.search, request));
  },
};
```

Вход через Google через запасной адрес не пойдёт: адрес возврата у Google привязан к домену проекта.

## Проверка

Правила базы проверяются на настоящем PostgreSQL, без обращения к Supabase:

```
supabase/local/start.sh        # поднять локальную базу со схемой и прогнать SQL-тесты
./gradlew :app:testDebugUnitTest --tests '*CloudApiTest*'
```

`local/tests.sql` проверяет правила доступа от имени разных людей (кто что может читать, менять, удалять)
и то, что скрипт не трогает чужие таблицы; `CloudApiTest` — клиент приложения поверх той же базы через
PostgREST. Регистрация и хранилище файлов в этих тестах изображаются (см. `FakeSupabase` в тестах).
Без локальной базы эти тесты пропускаются.

На настоящем проекте (ноябрь 2026) тем же клиентом и кодом раздела проверено: регистрация и вход, публикация
звука, пресета, трека и проекта, скачивание, оценки, счётчики, жалобы, модерация, лимиты хранилища,
удаление публикаций и аккаунта. Тестовые аккаунты и файлы после проверки удалены.
